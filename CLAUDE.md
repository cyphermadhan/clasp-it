# Clasp It — Claude Context

## What this is
A Chrome extension + hosted MCP server that lets developers click any webpage element and send its context to Claude Code. One click captures HTML, CSS, React props, console logs, network requests, and screenshot — delivered to Claude Code via MCP.

## Picker UX flow
1. User clicks "Pick Element" → picker activates (crosshair cursor, highlight overlay)
2. Hovering highlights elements (no dialog shown yet)
3. Clicking an element → picker deactivates → floating prompt dialog appears next to element
4. Dialog shows element label (tag.class), textarea, close (X) button, orange send (↑) button
5. Enter or send button → card added to sidebar history + picker re-activates
6. Shift+Enter = newline in textarea

## Floating dialog CSS isolation
All `#clasp-float-*` elements use `all: initial !important` to prevent host page CSS bleeding in.
Event listeners use bubble phase (not capture) so child button clicks aren't intercepted by parent.

## Server API
```
POST   /auth/signup                            — register email + deviceId (magic link sent)
GET    /auth/verify/:token                     — validate magic link → redirect to /verified
GET    /auth/poll/:deviceId                    — poll for magic link verification (no auth)
GET    /auth/info                              — email + plan for API key
POST   /element-context                        — store a pick (returns id)
PATCH  /element-context/:id                    — edit prompt; 409 if pulled
DELETE /element-context/:id                    — cancel pick + R2 cleanup + counter decrement
POST   /element-context/:id/attachments        — multipart upload (1+ files); 409 if pulled
DELETE /element-context/:id/attachments/:aid   — remove one attachment; counter decrements when last
GET    /element-context/quota                  — current month attachment quota
GET    /picks/statuses?ids=                    — status map for pick IDs
POST   /billing/checkout                       — create Dodo Pro checkout session
POST   /billing/checkout/topup                 — create Dodo top-up ($5 = +25) checkout
POST   /auth/webhook                           — Dodo webhook handler (subscription + payment events)
```

## MCP install command
```
claude mcp add --scope user --transport http clasp-it https://claspit.dev/mcp --header "Authorization: Bearer YOUR_API_KEY"
```

## Sidebar state machine
1. `loading` — check chrome.storage for API key
2. `auth` — email input → "Get free API key" (or paste existing key)
3. `verifying` — "check your email" + polls GET /auth/poll/:deviceId every 2s
4. `main` — pick button + history list (status badges) + gear icon + Claude tip (click-to-copy)
5. `picking` — "click any element..." + cancel
6. `picked` — (not used in quick-send flow; quick-send goes straight to main)
7. `settings` — email, plan badge, upgrade button, attachments quota card (Pro), Buy +25 button, API key, sign out, MCP setup
8. `edit` — opened by clicking a not_started history row; element label + prompt textarea + attachment thumbs (existing as filename chips, new as image previews) + paperclip + drag-drop + Save/Cancel

## History items
- Stored in chrome.storage.local (max 50 pro / 10 free)
- Each item: `{ id, pickId, elementLabel, pageURL, prompt, status, sentAt, attachmentCount?, attachments?, attachmentError? }`
  - `attachments[]` contains `{ id, filename, mimeType, sizeBytes }` for picks that have any. dataURLs are NOT stored locally — too heavy.
  - `attachmentError` is set when the upload failed; replaces the badge
- Status: `not_started | in_progress | completed` — polled from GET /picks/statuses every 5s
- `not_started` items: row is clickable (opens edit screen) and shows ✕ delete; other statuses show status badge
- ✕ on a not_started item with a server-confirmed pickId calls `DELETE /element-context/:id` first (best-effort), then removes locally
- Prompt text shown inline under element label; attachment count shown as "📎 N attachments"

## Coding conventions
- ES modules (`"type": "module"` in package.json)
- No TypeScript — plain JS throughout
- Graceful degradation: no `DATABASE_URL` → in-memory; no `REDIS_URL` → in-memory; no `R2_*` → attachment endpoints return 503
- Never use Stripe (invite-only in India) — Dodo Payments only
- Auth: accept both `X-API-Key` header and `Authorization: Bearer` in `requireApiKey` middleware
- Counter rules (symmetric): increment on FIRST batch upload to a pick; decrement on LAST attachment removal OR whole-pick delete. Clamped to ≥ 0.
- Attachment uploads route through the server (extension → server → R2). Extension never touches R2 directly.

## Infrastructure gotchas
- **Neon SSL**: always use `sslmode=require` in DATABASE_URL — never `sslmode=verify-full`. `db.js` adds `ssl: { rejectUnauthorized: false }` for Neon URLs as safety net.
- **Redis**: Railway-managed (likely Upstash via Railway integration). `REDIS_URL` is read-only on Railway; can't be edited. To run ad-hoc Redis commands, use `railway run` CLI rather than chasing an Upstash console — there isn't one.
- **Railway Root Directory = `server/`**: `nixpacks.toml` and the website build pipeline at the repo root are IGNORED. Build context is just `server/`. Start command must be `node index.js` (NOT `node server/index.js`). Website must be pre-built locally before commit.
- **Railway PORT**: do not set PORT manually — Railway auto-injects it. App listens on `process.env.PORT ?? 3001`.
- **DB outage = in-memory fallback**: wrong DATABASE_URL causes silent fallback. After fixing, users must re-authenticate.
- **CORS**: extension needs `host_permissions` in manifest for the server URL — reload extension after URL changes.
- **MCP auth test**: `curl https://claspit.dev/auth/info -H "Authorization: Bearer KEY"`
- **DNS**: claspit.dev uses ALIAS record on Porkbun (not CNAME — root domain restriction). TXT `_railway-verify` for Railway verification.
- **R2 signed URLs are method-specific**: signed for GET, so HEAD returns 403. Use a range GET to verify reachability.
- **R2 lifecycle policy**: not used. Cleanup happens via the daily Node sweeper (`server/lib/cleanup.js`). R2 has its own object lifecycle rules but we don't need them — the sweeper also cleans the DB.
- **MCP `update_pick_status({completed})` is the auto-cleanup trigger**: if Claude never calls it, files persist until the 28-day sweeper runs. The sweeper exists specifically to catch this.
- **Dodo signed-URL HEAD vs GET**: same pattern as R2 — HEAD returns 403 because the AWS-style signature is operation-bound.
